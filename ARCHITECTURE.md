# AppleIQ: відповідальність модулів та перевірка продуктивності

## Межі відповідальності

| Модуль | Відповідальність |
| --- | --- |
| `achievement-state.js` | Перевірка вхідних полів, щільності масивів і незмінні проєкції лише тих даних, які впливають на нагороди. |
| `appleiq-achievements.js` | Назви, умови секретів та колекційні нагороди AppleIQ. |
| `achievements-core.js` | Канонічний каталог, індекси ID, об’єднання нагород, сумісні адаптери резервної та хмарної копії. |
| `achievement-tracker.js` | Кеш поточного профілю, відстеження змін умов, синхронне збереження, повтор після помилки, синхронізація вкладок. Не використовує DOM або таймери. |
| `achievements-ui.js` | Лінивий список, пакетні DOM-записи через один RAF, життєвий цикл панелі та її обробників. Не визначає умови нагород. |
| `save-store.js`, `cloud-core.js` | Перевірка й відновлення прогресу гри; транзакційна заміна локальних записів разом з основним і резервним журналами досягнень. |
| `character-model.js` | Незалежне від роздільності малювання облич, костюмів і скелетних поз; отримує спільний gait solver, не володіє часом чи станом гри. |
| `scene-art.js` | Декорації та матеріали, спальня/клас/лікарня, вид із вікна, дерева, доповнення щасливих сцен та фон арени. Малювання до акторів; без власних циклів анімації. |
| `visual-polish.css` | Спільна палітра, панелі, доступні кнопки, адаптивне оформлення й повага до reduced motion. |
| `story.js` | Сюжетні переходи й керування часом сцени; малювання залишається в `cinema-details.js` та окремих модулях кінцівок. |

Старий API `GameAchievements.observe/mount/markup` та формат `{version:1, unlocked:[...]}` збережені. Тринадцять ID, умови, ігровий дохід і хмарний протокол не змінюються. Нові/перероблені модулі використовують ES6+, незмінні знімки й JSDoc для ключових контрактів.

## Прибрані зайві операції

Раніше кожне спостереження читало `localStorage`, повторно перевіряло каталог і перебудовувало весь список, навіть коли налаштування закриті. Тепер між значущими змінами використовується кеш. Час сцени проєктується у пороги нагород: наприклад, 10 і 24 секунди календаря мають однакову ознаку, а 25 секунд змінюють її. Незмінні внутрішні проєкції повторно використовуються через `WeakSet`, не утримуючи живі бойові об’єкти.

В UI рядки створюються одним `DocumentFragment` під час першого відкриття. Наступні нагороди змінюють лише відповідні рядки й лічильник. Кілька нагород за один такт дають один RAF. Від’єднані діалоги прибираються під час наступного монтування/оновлення; при звичайному виході видаляються всі обробники й очікуваний RAF, а повернення з BFCache відновлює синхронізацію.

У тренуванні DOM-вузли кешуються на час сцени. Для звичайного 3D-режиму немає додаткового читання геометрії DOM заради порожнього списку пласких яблук. При розташуванні спочатку читається розмір сцени, потім записуються позиції. На паузі цей цикл не виконує малювання чи DOM-записи.

## Вимірювання

Порівняння попереднього й нового коду в однаковому DOM-harness: **1000 однакових спостережень**, панель закрита, початкові нагороди вже отримані.

| Операція | До | Після |
| --- | ---: | ---: |
| Створення DOM-елементів | 39000 | 0 |
| Повне перебудування списку | 1000 | 0 |
| Читання сховища | 1000 | 0 |
| Записи незмінного профілю | 0 | 0 |

Це лічильники операцій, а не вимір FPS. Окремий тест виконує 10000 незмінних спостережень без читань/записів сховища. Тести також перевіряють відсутність читань layout у рендері досягнень та кешування DOM-вузлів тренування.

## Надійність

- Невідомі застосунки та ID, дублікати, розріджені масиви, нечислові рівні та нескінченні значення не приймаються.
- Основна й резервна копії мають той самий перевірений формат. Валідні нагороди обох копій об’єднуються після перерваного запису.
- Перед навігацією з кінцівки запис виконується синхронно. Помилка збереження залишає нагороди в пам’яті вкладки й показує повідомлення; наступне спостереження або життєвий цикл повторює запис.
- Вкладки об’єднують отримані нагороди. Хмарне завантаження зберігає попередній контракт заміни профілю й відкочує обидві локальні копії при помилці.
- Помилки відображення й зовнішніх слухачів не блокують збереження прогресу гри. Тексти списку вставляються через `textContent`.

## Подальші точкові зміни

Найбільший модуль, `story.js`, доцільно надалі розділяти по контролерах фаз. Кожен контролер має отримувати збереження й перехід через залежності та повертати один `dispose()`. Це варто робити окремими невеликими змінами з перевіркою паузи, відновлення та cleanup, а не одночасно з перенесенням усієї графіки. Резервні рендери не видаляються без доказу, що вони більше не використовуються.
